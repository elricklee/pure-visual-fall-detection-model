## 技术亮点

1. 纯视觉方案：只依赖普通摄像头视频，不依赖穿戴设备、雷达或深度传感器。
2. 可解释后处理：跌倒不是黑盒类别，而是由 bbox 宽高比、躯干角度、肩髋间距和时序状态共同决定。
3. 时序状态机：使用 `NORMAL -> SUSPECT_FALL -> FALL_CONFIRMED -> RECOVERY` 抑制单帧误报。
4. 多人隔离：通过 `track_id` 为每个人维护独立检测器和状态机。
5. 事件闭环：告警事件、截图、回放片段、逐帧 trace 和 HTML 报告可以同步生成。
6. 端侧准备：已提供固定输入 ONNX、INT8 QDQ 量化、算子审计、CPU 参考测速和 NPU 可行性说明。
7. 评估口径收敛：新增 `temporal_risk_score` 用于视频级 AUC，避免单帧尖峰主导排序。

## 不能夸大的点

- 不能说已经完成真实 NPU 实测。
- 不能把 PC CPU 的 19.0201ms 写成 NPU 延迟。
- 不能把伪红外当成真实红外传感器数据。
- 不能把 8 个带真值视频上的结果说成最终泛化精度。
- 不能把多人合成视频说成真实多人准确率评估。

这些限制不要藏起来。答辩时主动说明，反而显得工程口径可信。

## 当前主要短板

1. 数据集偏小，带真值视频数量不足。
2. 真实红外数据缺失，当前只有灰度复制的伪红外流程验证。
3. 真实多人场景没有充分标注验证，现有多人视频偏功能验证。
4. 没有实体 NPU 板卡，端侧延迟和运行内存仍为设计目标。
5. `run_system.py` 当前端到端 FPS 会受到视频解码、跟踪、绘制和文件写入影响，不应与纯模型推理速度混用。

## PPT 取胜叙事

推荐主线：不是“我们调了一个 YOLO”，而是“我们把纯视觉跌倒检测从模型训练推进到端侧可交付系统”。

建议 10 页结构：

1. 痛点与目标：居家养老/医疗照护跌倒风险，要求低成本、隐私友好、端侧可运行。
2. 总体方案：摄像头 -> YOLOv8n-pose -> 几何评分 -> 时序状态机 -> 多人事件中心。
3. 算法创新：连续风险评分 + 时序状态机，解释为什么能抑制误报。
4. 多人能力：`track_id` 独立状态机，避免多人状态串扰。
5. 系统闭环：标注视频、事件 JSONL、截图、回放、HTML 报告。
6. 模型轻量化：FP32/INT8 体积、参数量、QDQ 量化方案。
7. 评估结果：姿态 mAP、视频级 AUC/accuracy、FP32/INT8 一致性。
8. 端侧部署准备：固定 Shape、标准 ONNX 算子、NPU 转换风险分析。
9. 风险与边界：真实 NPU、真实红外、真实多人标注仍需后续补足。
10. 总结：一个可运行、可解释、可验证、可扩展的端侧跌倒检测 MVP。

## 推荐答辩金句

“我们的重点不是把跌倒当作单帧分类问题，而是把它建模成一个连续事件：先由人体关键点产生可解释风险分数，再由时序状态机确认和恢复，最后按人员 ID 生成可追溯的告警事件。”
